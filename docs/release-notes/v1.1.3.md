# v1.1.3 — release builds, battery health, storage speed, a tile

Phone Diagnostic Tool **1.1.3** (versionCode **30**).

## Security: the download is now the release build

Every release up to and including 1.1.2 shipped the **debug** build. That APK carried `android:debuggable`, the Compose tooling libraries and no minification. Two consequences: with USB debugging on, `run-as` gave a connected host full read of the app's private data — and the download was **16.9 MB where the release build is 1.2 MB**.

The signing key is unchanged, so this installs straight over 1.1.2 with no uninstall.

One thing this does **not** fix: that signing key's private half is committed in the public repository, so anyone can build an APK bearing the same certificate — which Android would accept as an update. That is written up in [docs/SECURITY-AUDIT.md](https://github.com/ScoobyDouche/PhoneDiagnosticTool/blob/main/docs/SECURITY-AUDIT.md) along with what fixing it costs. Install from the Releases page here and you have the real build.

## Battery health

Two figures on the Battery screen, from two different sources, either of which can be present without the other.

**Charge cycles** — how many full cycles the battery has been through. Public since Android 14, read from the battery-changed broadcast. This is the more useful wear signal of the two, and it is measured rather than inferred.

**Capacity health** — remaining capacity as a percentage of the factory rating, where the fuel gauge exposes both figures and the ratio is physically sensible. Most phones deny apps access to those nodes, and an uncalibrated gauge can claim more than 100% of a new battery.

Where neither is available the screen says which route is closed and why, rather than showing a number. Android does have its own state-of-health percentage, but it is a system API — no ordinary app can read it, and any app showing you one on every device is estimating without saying so.

## Charging power

Live watts, in or out, from voltage times current. The number you want when asking whether a charger or cable is actually doing its job.

## Storage speed test

In **Tools**. Writes a 64 MB file to the app cache, reads it back, reports sequential throughput, deletes it.

Two details that make the figure honest: the buffer is filled with varied bytes, so a compressing or deduplicating storage layer cannot report a speed the device could never sustain on real data; and the write is `fsync`ed, so it measures flash rather than the page cache. It refuses to run without 320 MB free, and cleans up on every exit path.

## Quick Settings tile

Battery temperature and RAM use in the notification shade. It samples battery and memory only; a full collect would spin up a GPU context and wake every sensor each time you pulled the shade down.

Third-party tiles are never added to the shade automatically, and hunting for one among the inactive tiles is the step everybody misses — so **Settings → Quick Settings → Add to Quick Settings** asks the system to offer it in one tap. That prompt needs Android 13; below it, the same section tells you where to look.

## Also fixed

The **Storage screen was never localised** — 37 string resources had been written for it and never wired in, so it stayed English regardless of device language. The 1.1.0 claim of full localisation was wrong about that one screen. Sensor detail also numbered its fourth and later axes with a hardcoded label.
