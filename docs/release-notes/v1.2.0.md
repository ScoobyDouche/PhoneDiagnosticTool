# v1.2.0 — optional elevated access (Shizuku / root)

Phone Diagnostic Tool **1.2.0** (versionCode **31**). Installs over 1.1.3 in place.

## Optional elevated access (opt-in, off by default)

Some hardware values sit behind sysfs permissions an ordinary Android app cannot
get — the battery fuel gauge is the headline one. A new **Elevated access**
section in **Settings** lets you opt into reading them, and only if you choose to.

Three tiers:

- **Off** — the default. No elevated reads, nothing bound, no extra process. The
  app stays a no-permissions diagnostic tool.
- **Shizuku** — small read-only commands run as the shell user (UID 2000), the
  same reach as `adb shell`. No root, and nothing permanent to the device. You
  install and start the [Shizuku](https://shizuku.rikka.app/) app once, then grant
  this app access with one tap. Settings shows whether Shizuku is installed,
  running, and has granted access.
- **Root** — the same read-only commands run through `su`, reaching nodes even
  the shell user cannot.

The chosen backend is used **only as a fallback** when the normal read is denied,
so devices that already expose a node are completely unaffected.

## What it unlocks

- **System-wide process list.** With Shizuku (or root), the RAM detail screen
  shows **every running process** from `dumpsys meminfo`, with **per-process CPU
  load** merged in from `dumpsys cpuinfo` — instead of the self-only view Android's
  `hidepid` otherwise limits apps to.
- **Battery fuel gauge.** The capacity-health percentage and charge cycles can now
  appear on devices that block those nodes from apps but allow the shell or root to
  read them. Where the discrete nodes are blocked but the aggregate
  `/sys/class/power_supply/*/uevent` is readable (common on Samsung), the figures
  are parsed from that instead; cycles fall back to the kernel-standard
  `POWER_SUPPLY_CYCLE_COUNT` when the Android 14 broadcast field is absent. Still
  never estimated — if the gauge does not give a real figure, the screen says so.
- **Per-core CPU clocks** recovered on devices that have locked `scaling_cur_freq`
  down to apps.
- **"Read via Shizuku / root" markers.** Any value that was only obtainable through
  elevated access is tagged as such on the Battery, CPU and RAM screens, so it is
  visible which readings the feature actually unlocked on your device.

Whether a specific node is reachable varies by vendor and Android version — the
shell user gets many of them, root gets more, and a locked-down device may still
withhold some (the battery gauge on recent Samsung, for instance, tends to need
root).

## Also in this release

- **Thermal load-test mode.** A heavier CPU stress option that adds transcendental
  math and strided memory thrashing on top of the FPU loop to push more heat. The
  standard benchmark is unchanged; the thermal score is labelled not-comparable.
- **Load test runs on every core.** It previously used a fixed 4 threads; it now
  spawns one worker per CPU core, so it saturates the whole processor.
- **Multi-touch pad fixed.** It showed only the highest finger count seen; it now
  shows the live count of fingers currently down (which falls as you lift them)
  alongside the session peak.

## A word on root

Rooting can trip a hardware fuse (Samsung Knox, for one) that permanently disables
secure features, and can break banking and wallet apps. That is your decision to
make — the app only ever reads, and the Settings copy says as much before you pick
it. Shizuku carries none of that cost.

## Privacy

Unchanged posture: everything runs on-device, and elevated commands are limited to
reading diagnostic values shown on screen. Nothing about this is transmitted
anywhere, and no elevated access is used or bound while the feature is Off. See
[PRIVACY.md](https://github.com/ScoobyDouche/PhoneDiagnosticTool/blob/main/PRIVACY.md).
