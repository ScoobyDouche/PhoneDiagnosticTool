# v1.2.1 — Usage Access, when Android refuses to grant it

Phone Diagnostic Tool **1.2.1** (versionCode **32**). Installs over 1.2.0 in
place — no uninstall needed.

One fix, reported from the field on a Pixel 6 Pro.

## The per-app storage breakdown could not be turned on

**More → Storage** lists how much space each app uses, which needs the Usage
Access permission. Tapping **Open Usage Access** landed on the right Settings
screen, but flipping the toggle there answered with:

> **App was denied access** — Access to this permission can put your personal and
> financial info at risk.

Nothing was broken in the app. Android 13 made Usage Access a *restricted
setting* for apps that did not arrive through the Play Store, and this one is
installed from a GitHub Release. The unblock exists, but it lives on a different
screen than the one that refuses you, and nothing on that screen says so — which
leaves the feature looking permanently broken.

It is granted like this:

1. **Settings → Apps → Phone Diagnostic**
2. **⋮** (top right) → **Allow restricted settings**, confirmed with your PIN or
   biometrics
3. Back in the app: **Storage → Open Usage Access**, and the toggle now works

So the storage screen now says that itself. When the app is running on Android 13
or newer and was installed by something other than the Play Store, the permission
card carries the three steps and an **Open App info** button that goes straight
to the screen holding the menu. The README covers the same ground for anyone who
hits it before opening the app.

The restricted state is not something an app can query, so this is inferred from
the Android version and the installing package rather than read. A wrong guess
shows one extra paragraph of guidance to somebody who did not need it, which is
the right way round for this trade.

Overall volume sizes never needed Usage Access and were unaffected throughout.

## Also

Both CI workflows had started failing 20 seconds into every run, before a line of
the project was compiled: `android-actions/setup-android` installs
`tools platform-tools` by default, and Google has withdrawn the obsolete `tools`
package from the SDK repository. The release workflow carried the same step, so
this release could not have been built at all. Both now ask for the packages the
project actually builds against.
